# Forge Documentation & CLI Experience Standard v1

Shared standard for every Forge repository. Each forge may specialize,
but a user moving between forges must never relearn the basics. No forge
needs the-forge installed to read or use another forge's docs.

## 1. Information architecture

```text
README.md                      # first contact — see §3
docs/
├── installation/              # per-host install guides (Phase 5)
├── reference/
│   ├── commands.generated.json   # inventory, machine-made (Phase 0)
│   ├── divergence.generated.json # doc↔CLI drift report
│   ├── commands.md               # curated command reference (Phase 3)
│   ├── skills.md                 # skills catalog (Phase 6)
│   ├── agents.md                 # agents catalog (Phase 6)
│   └── mcp.md                    # MCP server + tools (Phase 7)
├── tutorials/                 # task-first walkthroughs (Phase 8)
├── troubleshooting.md         # symptom → cause → fix (Phase 9)
└── economy.md                 # tokens/context economy (Phase 15)
```

## 2. Language policy

Primary language: **English** for reference material; the forge's
existing working language (pt-BR where established) for guides. Main
flows — README quickstart, installation, troubleshooting — exist in
**both** pt-BR and EN. Reference pages stay single-language to avoid
translation drift; the gate checks parity only where declared.

## 3. README structure (mandatory order)

1. **O que é / What it is** — one paragraph, no architecture.
2. **Install** — the three-command flow (clone → setup → install).
3. **First use** — smallest real command + expected output.
4. **Discover** — `capabilities`, `--help`, docs links.
5. **Reference** — links into `docs/`, not inline duplication.
6. **Status & limitations** — honest `UNVERIFIED`/`BLOCKED` items.

## 4. Command reference template (Phase 3)

Every public command page uses the fixed section order:

`what it does → when to use → syntax → prerequisites → basic example →
what happens internally → files created → interpreting output → next
step → common errors → advanced examples → technical references`

Sections with no content are written as `N/A` — never silently omitted.

## 5. Command metadata (Phase 12 schema)

Reference pages carry YAML frontmatter:

```yaml
id: <forge>.<verb>[.<sub>]
title: short title
status: available | experimental | deprecated
audience: beginner | intermediate | advanced
category: install | analyze | lifecycle | utility
risk: read-only | writes-managed | mutates-user | external-side-effects
requires_network: bool
requires_credentials: bool
```

`status: planned` or `deprecated` must state migration guidance.

## 6. Examples

Every example is classified: `offline` (testable, safe), `host`
(requires AI host), `credentials`, `cloud`, `manual`, `illustrative`
(never runs — marked as such). Offline examples run in the doc gate.

## 7. CLI message standard

- Bare invocation prints summary + top commands + how to get help —
  never a stack trace, never a mutation.
- Unknown command → `Did you mean:` suggestions from real verb names.
- Mutations require explicit approval (`--yes`); `--dry-run` plans.
- Errors name the contract kind (`FORGE-*`/repo prefix), the cause,
  and the next action.

## 8. Naming

CLI names are kebab-case verbs (`install`, `doctor`, `capabilities`).
No synonyms with conflicting semantics; legacy aliases are preserved
with a deprecation note pointing at the canonical name.

## 9. Deprecation policy

A command is `deprecated` in docs + help for ≥1 minor release before
removal. Docs list the replacement on the same page.

## 10. Versioning & ownership

Docs ship in the same commit as the behavior they describe.
`commands.generated.json` and `divergence.generated.json` are build
artifacts — regenerated by `scripts/docs/doc_inventory.py`, never
hand-edited. The doc gate (`scripts/docs/check_docs.py`) is a commit
gate, not advisory.

## 11. Quality bar per repository (Phase 16)

README answers the 6 mandatory questions; every public command appears
in the generated reference; zero broken internal links; zero
documented-but-missing commands; offline examples verified; honest
status labels — `pending`/`unverified` never claimed as delivered.

## 12. What this standard is not

Not a runtime dependency: docs are plain markdown readable without
any forge installed. Not a reason to hide risk: mutating, credential,
or networked commands say so in `risk:` and in the page.
